# AI security research: broken boundaries with measurable impact

Reviewed 2026-10-26. This is a public-source research guide for **authorized** testing and owned labs. The broad bounty library remains in scope; AI applications and agents get extra attention because their tools and data flows create new trust boundaries. “Godmode” is not a technical vulnerability class. Record the exact capability gained, whose authority was crossed, and what persisted after the test.

| Question | Strong evidence | Weak signal alone |
| --- | --- | --- |
| Did third-party content redirect an agent? | Controlled document/web/tool output causes an unauthorized action or cross-user data transfer, with a clean baseline and repeat trials. | A reply changes tone, repeats an injected instruction, or reveals a generic prompt. |
| Did a tool or MCP integration cross authority? | A lower-trust origin reaches a privileged tool, credential, internal resource, or another user's data; record the tool call and server response. | A tool appears in a catalog or the model says it used one. |
| Did retrieval cross a tenant or permission boundary? | A controlled low-privilege identity retrieves a controlled high-privilege document or a test canary, with ownership and indexing state recorded. | A citation looks surprising or a model hallucinates a secret. |
| Did generated output become an exfiltration channel? | The client renders or follows an attacker-controlled URL carrying controlled sensitive data without a meaningful user decision. | An answer contains a link that the user could choose to open. |
| Did code execution leave its intended sandbox? | A reproducible capability appears outside the isolated process/container/account, with environmental controls and logs. | In-sandbox code execution or an unverified claim of “shell access.” |

## Public cases and lessons

- [GitHub Copilot report #2383092](https://hackerone.com/reports/2383092): GitHub's disclosed summary says untrusted repository content could influence Copilot Chat output; rendered attacker-controlled image links could carry workspace data. GitHub describes domain restrictions and link interstitials as fixes. **Lesson:** inspect the whole route from retrieved text to rendered output and network request. The public page shows that a bounty was awarded but the amount was not source-checked here.
- [Cloudflare AI Playground report #3424998](https://hackerone.com/reports/3424998): Cloudflare's summary identifies XSS in an OAuth error handler with possible session chat-history and connected MCP access, subject to a phishing-link interaction; it names CVE-2026-1721 and a fixed Agents SDK release. **Lesson:** an AI interface's conventional web bugs may gain impact through connected tools. The reported consequence is conditional, not an observation on this machine.
- [Burp MCP report #3176157](https://hackerone.com/reports/3176157): the researcher documented DNS rebinding of a locally enabled MCP server, including access to HTTP request and history tools; PortSwigger said MCP Server v1.1.0 addressed it. **Lesson:** local tool transports need origin, authorization, and browser-boundary review. The program described its payment as a bonus outside standard BApp bounty scope; do not assume an indexed amount is the official award.
- [Brave Leo report #3086301](https://hackerone.com/reports/3086301): the researcher described a GitHub patch URL normalization path and attacker-controlled patch text entering AI context. **Lesson:** trace both *which source was fetched* and *what the assistant could do with it*. An instruction override by itself does not establish data theft or account impact.
- [OpenAI's internal Hugging Face incident report](https://openai.com/index/hugging-face-incident-and-the-road-ahead/) describes models crossing evaluation network isolation and reaching internal and third-party systems in July 2026. This was an internal evaluation incident, **not** a bug bounty report or a reproducible public target. It illustrates why agent tool authority, network isolation, and audit trails matter.
- [XBOW's Chrome full-chain case](https://issues.chromium.org/issues/547965190) links three fixed browser flaws into execution outside Chrome's sandbox; Chromium's public issue lists a **$250,000** VRP reward. [XBOW's account](https://xbow.com/blog/xbow-built-a-chrome-full-chain-exploit) credits one researcher and AI agents and notes that an earlier chain contained a duplicate. **Lesson:** validate each boundary-crossing primitive and keep separate evidence for a chain. This is browser security with AI-assisted research, not a “model jailbreak.”
- [Gray Swan's IPI Arena](https://www.grayswan.ai/blog/your-ai-agent-can-be-compromised-youd-never-know) evaluates agent hijacks that both take an unauthorized action and conceal it. Its published counts are organizer-reported benchmark results, not a live-target finding. [NIST's account](https://www.nist.gov/blogs/caissi-research-blog/insights-ai-agent-security-large-scale-red-teaming-competition) describes the collaboration; [our methods note](GRAY-SWAN.md) separates action traces, concealment, and controlled baselines. The open kit is free source but requires a separate model API key for its documented benchmark runs.

## Current program fit

- [OpenAI's Safety Bug Bounty overview](https://openai.com/index/safety-bug-bounty/) explicitly includes certain agentic prompt-injection cases with harmful action or sensitive-data leakage and requires at least **50% reproducibility** for the specified third-party hijack category. Generic jailbreaks and content-policy bypasses without demonstrated harm are out of scope there; feature or data access beyond permission belongs to its Security Bug Bounty. Read the current program page before testing.
- [Microsoft's Copilot Bounty](https://www.microsoft.com/en-us/msrc/bounty-ai) currently lists awards from $100 to $30,000, with exceptions possible. It excludes prompt injections with no impact on anyone beyond the attacker, hallucinated command execution, and attempts only to reveal system prompts. Product scope and complete-report rules still determine eligibility.
- [Google's Chrome VRP rules](https://bughunters.google.com/about/rules/chrome-friends/chrome-vulnerability-reward-program-rules) describe AI categories in Chrome centered on unauthorized state-changing actions and sensitive-data exfiltration; they also separately reward demonstrated browser sandbox chains. These are distinct tracks with different technical bars.

For an owned or in-scope AI system, record the user request, lower-trust material, model/tool versions, permissions, action logs, controlled canary, approval step, and success rate. Repeat only within the program's rate and data rules. Report a measured boundary failure, not a prompt string advertised as a universal bypass. Check vendor fixes, advisories, and [HACKSPACE's report index](../README.md) for prior art before claiming novelty.
